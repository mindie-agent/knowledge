# 社区贡献与外发规范

中文 | [English](community-sharing.md) · [返回文档索引](README.md)

本文说明贡献者端的社区共享开关、发件箱打包与 GitHub PR 提交对账流程。

## 1. 显式授权与状态区分

- 社区共享默认关闭，仅在用户通过配置命令明确启用并指定授权项目范围后生效。
- 状态查询清晰区分：`unconfigured`（尚未选择）、`disabled`（显式关闭）、`scope_mismatch`（项目不在授权范围）与运行期错误。
- 用户随时可关闭共享：关闭后立即阻止一切未发送的外发动作，且重新开启不会回放关闭期间的对话。

## 2. 发件箱构建与闭锁式脱敏

- 仅当任务分块已完成原生小模型导航索引、生成完整 `PACKAGE.md` 且全部文件通过 `mindie_knowledge.redact` 与 Gitleaks 复检后，才可进入外发批次（`mindie-contribution/1`）。
- 任何脱敏规则命中或格式不合规均触发闭锁式中止（Fail-Closed），阻止构建外发分支或提交 PR。

## 3. 远端写入与 `unknown` 只读对账

- 外发工作器向公开知识仓库推送分支并创建 PR，保存精确的提交 SHA 与 PR 回执。
- 若推送或创建 PR 期间发生网络超时或进程中断，该批次标记为 `unknown`；后续恢复必须先通过只读 GitHub 查询核对远端分支与 PR 是否已存在，严禁盲目重复推送或创建重复 PR。
