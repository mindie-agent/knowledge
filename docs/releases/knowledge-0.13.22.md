# mindie-knowledge 0.13.22：共享存储生命周期、跨 Harness 静默历史回收与 Windows 短键修复

[English](knowledge-0.13.22.en.md)

- **新增共享存储生命周期包（`mindie_knowledge/storage/`）**：`leases.py` 提供跨平台产物活性判定——POSIX 通过 `.inuse.lock` 的 `LOCK_SH|LOCK_NB` 共享租约，Windows 额外持有不带 `FILE_SHARE_DELETE` 的 `.inuse.<pid>.<uuid>.lease` 打开句柄，使 NTFS 上的 `os.replace(<dir>, ...)` 在目录仍被使用时原子失败；`live_process_prefixes()` 在 POSIX 仅执行有界 `ps -ww -axo command=`，非零退出、超时或输出封顶一律 `inspection_complete=False`，绝不回退到 80 列截断表；在 Windows 通过 `kernel32` 的 Toolhelp32 + `QueryFullProcessImageNameW` 原生枚举，**零控制台子进程、零弹窗**。检测失败返回 `inspection_complete=False`，绝不把“看不见进程”当作“可以删除”。
- **两阶段 `.trash-*` 退役与 Windows 扩展路径**：`retire_directory()` 先以单次 `os.replace` 把候选目录原子移出可用命名空间，失败（`PermissionError`/`WinError 5`/`WinError 32`）时返回 `deferred_in_use` 且**不删除源目录内任何文件**；Windows 退役句柄全部位于候选目录之外（同级 `.mindie-retire.lock`，候选目录内零打开句柄），避免 NTFS 拒绝重命名；`sweep_trash()`/`prune_component_runtimes()` 直接拒绝符号链接或 junction 根，配置的 `source_root`/`package_dir` 也作为祖先保护域。随后在 deadline 内按扩展路径 `\\?\...` 删除 `.trash-*`，只读 `.git` packfile 通过 `os.chmod(..., S_IWRITE)` 修复。截止时间或扫描器占用只留下可续删的 `.trash-*`，由下一次 `sweep_trash()` 完成。`prune_component_runtimes()` 同时区分已验证 `components.json` 与失败半成品：无清单且超过 `1800s` 的 230 MiB 级 `.venv` 会被回收，新的 staging 构建保持不变。
- **同卷 UV 缓存自动选择**：`configure_same_volume_uv_cache()` 比较 uv 默认缓存（macOS `~/Library/Caches/uv`、Windows `%LOCALAPPDATA%\uv\cache`、Linux `${XDG_CACHE_HOME:-~/.cache}/uv`）与目标代的 `st_dev`；跨卷/跨盘（`EXDEV` 导致每个代 250 MB 全量复制）时改用目标父目录下的 `.uv-cache`，恢复 APFS `clonefile` 与 NTFS/Linux hardlink。调用方显式设置的 `UV_CACHE_DIR` 永不覆盖。
- **Windows 短目录键（`P2.4`/`P1.6`）**：`generation_key()` 继续返回 64-hex（外部调用与既有测试 100% 兼容）；新增 `generation_dir()`：已存在 64-hex 目录原样复用，Windows 上改用 `key[:24]`，使 `<root>/<24hex>/runtime/.venv/Scripts/pythonw.exe` 稳定低于 260 字符的 Task Scheduler 限制；仅当短目录无 `components.json`/`prepare.lock` 的极端前缀碰撞才回退到 `key[:32]`。
- **构建前/构建后 GC、失败清理与运营入口**：`component_runtime.build()` 在 `uv sync` 前、`prepare.lock` 之外运行受限 Pre-Build GC（`min(8s, max(1s, timeout*0.1))`，任何非超时清理警告都不阻塞构建），释放接近写满的卷；验证通过后再以 3s 预算、600s 冷却静默执行一次跨 Harness 历史回收（组件自更新即可触达）；所有新鲜构建路径（含 `uv sync`、源一致性校验、`runtime_inventory.py` 验证）异常时清理 `generation/runtime`、`generation/source` 与 `.pending.json`，不再遗留无 `components.json` 的未验证 `.venv`。`python -m mindie_knowledge.component_runtime` 新增 `prune` 与 `sweep_legacy` 操作，供宿主插件直接调用。
- **跨 Harness 静默历史回收（`sweep_legacy_installations`）**：在 `0.13.22` 激活后（即使仅由后台组件自更新触发）自动、静默回收 Kimi/Codex/CC/DSH/AGY/WB/OC 七个 Harness 的历史包袱。回收前统一闭包保护：当前解释器/前缀；`~/.config/mindie-agent`（Windows 另含 `%APPDATA%`/`%LOCALAPPDATA%`）下全部配置值；Kimi `current.json` + 仅 `current.sha` 的直接 `previous` 回滚（不递归历史 receipts）；DSH `current.json` 的 `generation`/`previous_generation`；Diagnostics `source_hash`/`previous_source_hash`；以及四处实证隐藏宿主 pin——Claude Code `entry.py`、Kimi `mindie-front`/plist/`MindIEKimiUpdate.pyw`、DSH profiles `node_modules` 链接、WorkBuddy `mcp.json`/`hooks.json`。WB/OC/AGY 借用 Codex/CC/Kimi 的 `python` 会反向保护其所属代。清理范围严格限定 MindIE 托管目录，绝不触碰用户 Git checkout 或 `RemoteReceipts`（`gate-v1/*.sqlite3`），并以 `<data_home>/.storage-gc-state.json` 做 600s 冷却（`force=True` 或残留 `.trash-*` 可绕过）。后台知识服务 `_serve` 启动后同享该受限清扫（5s 预算、非抛错），覆盖“知识服务先于宿主插件更新”的真实升级路径。
- **其余知识目录泄漏修复**：`release_http.py` 除 `http-*.json` 外同时修剪旧版 `<64hex>.json` 并清理超过 1 小时的 `*.tmp`；`loop/process.py` 在 `_spawn` 抛 `TimeoutError`/任意异常时删除已创建的 `mindie-summary-owner-*`，且 reader 关闭检查抛 `RuntimeError` 时仍在内层 `finally` 清理 scratch；`summary_scratch.py` 写入显式 `.mindie-owner.json`，仅对“Marker 证明归属 + 写者进程已退出 + 超过 1 小时”的 `mindie-summary-owner-*`/`mindie-distill-*` 做机会式清扫；`.windows-service/` 与 `.systemd-service/` 的终结 attempt 回执按 24h/最新 32 个 attempt 修剪；`feed.py` 在 staging 期间遇到 `TimeoutError`/`InterruptedError` 时清理 `staging/<commit>` 后再抛出原始异常；`transcript_redaction.py` 注册 `atexit` 清理 `mindie-redaction-*`；`tests/conftest.py` 在会话结束时删除 `mk-iso-*` 根目录（xdist worker 不会误删共享根），并以硬链接优先复用 28 MB Gitleaks 缓存。
- **验证**：新增 `tests/test_storage_lifecycle.py` 真实目录/真实锁/真实子进程的 Tier 0 & Tier 1 覆盖——七 Harness 假用户主目录的回收与幂等、运行中子进程保护、Windows `PermissionError` 原子退役安全（零文件被删）、失败构建清理 + Windows `<24hex>` 短键 + 跨卷 `UV_CACHE_DIR` 选择、`release_http` 旧缓存/临时文件修剪与 `loop/process.py` 超时 scratch 清理。全部核心模块保持 `< 800` 行与 `[Role]`/`[Invariants]`/`[Timeouts & Locks]`/`[Side-Effect Policy]` 头，Unix `LF` 行尾。
