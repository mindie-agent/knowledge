# mindie-knowledge 0.13.22: shared storage lifecycle, silent cross-harness legacy reclamation, and Windows short keys

[中文](knowledge-0.13.22.md)

- **New shared storage lifecycle package (`mindie_knowledge/storage/`)**: `leases.py` provides cross-platform artifact liveness. POSIX holds a shared `LOCK_SH|LOCK_NB` lease on `.inuse.lock`; Windows additionally keeps an `.inuse.<pid>.<uuid>.lease` handle open without `FILE_SHARE_DELETE`, so NTFS `os.replace(<dir>, ...)` fails atomically while the directory is in use. `live_process_prefixes()` runs only a bounded `ps -ww -axo command=` on POSIX (a non-zero exit, timeout or capped output is `inspection_complete=False`; there is no 80-column fallback) and uses native `kernel32` Toolhelp32 + `QueryFullProcessImageNameW` on Windows — **zero console subprocesses and zero popups**. A failed inspection returns `inspection_complete=False` and never treats "no process seen" as permission to delete.
- **Two-phase `.trash-*` retirement with Windows extended paths**: `retire_directory()` atomically moves a candidate out of the reusable namespace with one `os.replace`. A failure (`PermissionError`/`WinError 5`/`WinError 32`) returns `deferred_in_use` without deleting a single file inside the source directory. Windows retirement keeps every lock handle outside the candidate (a sibling `.mindie-retire.lock` with zero open handles inside it), so NTFS never rejects the rename; `sweep_trash()`/`prune_component_runtimes()` refuse symlinked or junction roots, and configured `source_root`/`package_dir` trees are protected ancestors. It then removes `.trash-*` within the deadline through `\\?\...` paths, repairing read-only `.git` packfiles with `os.chmod(..., S_IWRITE)`. A deadline or transient scanner leaves a resumable `.trash-*` for the next `sweep_trash()`. `prune_component_runtimes()` distinguishes verified `components.json` generations from failed half-builds: a manifest-less `.venv` older than `1800s` is reclaimed while fresh staging is preserved.
- **Automatic same-volume uv cache**: `configure_same_volume_uv_cache()` compares the `st_dev` of uv's default cache (macOS `~/Library/Caches/uv`, Windows `%LOCALAPPDATA%\uv\cache`, Linux `${XDG_CACHE_HOME:-~/.cache}/uv`) with the target generation. On a cross-volume/cross-drive layout (`EXDEV`, which previously forced a 250 MB full copy per generation) it selects `.uv-cache` beside the target, restoring APFS `clonefile` and Windows NTFS/Linux hardlinks. An explicit caller `UV_CACHE_DIR` is never overwritten.
- **Windows short directory keys (`P2.4`/`P1.6`)**: `generation_key()` keeps returning the full 64-hex digest (100 % compatible with external callers and existing tests). The new `generation_dir()` reuses an existing 64-hex directory verbatim and otherwise uses `key[:24]` on Windows, keeping `<root>/<24hex>/runtime/.venv/Scripts/pythonw.exe` comfortably below the 260-character Task Scheduler limit. Only an aborted, manifest-less prefix collision falls back to `key[:32]`.
- **Pre-build/post-build GC, failure cleanup and operator entry points**: `component_runtime.build()` runs a bounded Pre-Build GC before `uv sync` and outside `prepare.lock` (`min(8s, max(1s, timeout*0.1))`; any non-timeout cleanup warning never blocks the build), freeing space on nearly full volumes. After verification it also runs one 3 s, 600 s-cooldown cross-harness reclamation, so a background component auto-update alone delivers legacy cleanup. Every fresh build path (`uv sync`, retained-source comparison, `runtime_inventory.py` verification) now removes `generation/runtime`, `generation/source` and `.pending.json` on failure, so an unverified 250 MB `.venv` without `components.json` is never stranded. `python -m mindie_knowledge.component_runtime` exposes `prune` and `sweep_legacy` operations for host plugins.
- **Silent cross-harness legacy reclamation (`sweep_legacy_installations`)**: once `0.13.22` activates — even when only a background component auto-update delivers it — historical baggage is reclaimed silently across all seven harnesses (Kimi/Codex/CC/DSH/AGY/WB/OC). Before any retirement one protected closure is unioned: the running interpreter/prefix; every value under `~/.config/mindie-agent` (plus `%APPDATA%`/`%LOCALAPPDATA%` on Windows); Kimi `current.json` and only the immediate `previous` rollback of `current.sha` (never the whole historical receipts chain); DSH `current.json` `generation`/`previous_generation`; Diagnostics `source_hash`/`previous_source_hash`; and the four empirically verified hidden host pins — Claude Code `entry.py`, Kimi `mindie-front`/plist/`MindIEKimiUpdate.pyw`, DSH profiles `node_modules` links, and WorkBuddy `mcp.json`/`hooks.json`. A WB/OC/AGY borrowed `python` pointing into Codex/CC/Kimi protects its owning generation. Sweeping is limited to MindIE-managed directories and never touches user Git checkouts or `RemoteReceipts` (`gate-v1/*.sqlite3`); `<data_home>/.storage-gc-state.json` enforces a 600 s cooldown (`force=True` or leftover `.trash-*` bypasses it). The background knowledge service's `_serve` shares the same bounded, non-throwing sweep (5 s budget), covering the real upgrade path where the knowledge service updates before its host plugins.
- **Remaining knowledge-directory leak fixes**: `release_http.py` now prunes legacy `<64hex>.json` files alongside `http-*.json` and removes `*.tmp` files older than one hour; `loop/process.py` deletes the created `mindie-summary-owner-*` when `_spawn` raises `TimeoutError` or any other exception, and cleans scratch in an inner `finally` even when the reader-close check raises `RuntimeError`; `summary_scratch.py` writes an explicit `.mindie-owner.json` and opportunistically sweeps `mindie-summary-owner-*`/`mindie-distill-*` only when the marker proves ownership, the writer has exited and the directory is over an hour old; `.windows-service/` and `.systemd-service/` terminal attempt receipts are pruned beyond 24 hours or the newest 32 attempts; `feed.py` clears `staging/<commit>` before re-raising `TimeoutError`/`InterruptedError` during staging; `transcript_redaction.py` registers an `atexit` cleanup for `mindie-redaction-*`; `tests/conftest.py` removes the `mk-iso-*` root at session finish (an xdist worker never deletes the shared root) and hardlinks the 28 MB Gitleaks cache instead of copying it.
- **Verification**: the new `tests/test_storage_lifecycle.py` adds real Tier 0 & Tier 1 coverage with real directories, locks and subprocesses — a seven-harness fake home sweep plus idempotency, live-subprocess protection, Windows `PermissionError` atomic-retirement safety (zero files deleted), failed-build cleanup + Windows `<24hex>` short keys + cross-volume `UV_CACHE_DIR` selection, `release_http` legacy-cache/stale-temp pruning, and `loop/process.py` timeout scratch cleanup. Every core module stays under 800 lines with the `[Role]`/`[Invariants]`/`[Timeouts & Locks]`/`[Side-Effect Policy]` header and Unix `LF` endings.
