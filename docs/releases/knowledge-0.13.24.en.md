# mindie-knowledge 0.13.24: First-Class `local-only` Consent, Capture/Publication Separation, Anonymous HTTPS Public Sync, and Password Redaction Hardening

[中文](mindie-knowledge-0.13.24.md)

`mindie-knowledge v0.13.24` promotes `local-only` to a first-class consent choice and splits local capture from GitHub publication into two independent authority chains:

- **First-class `local-only` tier (`mindie-consent/1`)**: `CHOICES` gains `local-only`; `consent_store.record_choice` remains the sole writer and keeps the monotonic `choice_revision`. `activate_reporting` enables diagnostics upload only for a saved `contribute + choice_revision`; `local-only` writes a disabled reporting policy, returns `status="disabled"`, and starts no worker.
- **Capture and publication authority separated (`allows_capture` / `allows_publication`)**: `loop/settings.py` exposes `effective_tier`, `allows_publication`, and `publication_block_kind`. `PublicationWorker`, the engine outbox, `community.settings.live_gate`, `community.publish`, and read-only reconciliation all consult publication authority. Under `local-only` (or `local_only=true`), stale on-disk `fork`/`account` fields cannot construct a transport, invoke `gh`, check a fork, freeze an outbox batch, or create a PR.
- **No backfill across `local-only` → `contribute`**: captures, material, and locally distilled units carry additive `origin_tier` metadata (without changing `state-v4.sqlite3`, `FORMAT = 1`, `MaterialStore` `DATA_FORMAT_V1`, or existing readers). Anything stamped `origin_tier=local-only` stays permanently ineligible for a later `contribute` export.
- **Pure anonymous HTTPS public feed sync**: `clone`/`fetch` for the canonical public corpora (`https://github.com/mindie-agent/knowledge-*`) pass `GIT_TERMINAL_PROMPT=0` and `-c credential.helper= -c core.askPass= -c http.extraHeader=`, so a host with no `gh` or a broken credential helper still reads the public feed anonymously. Enterprise `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`/`SSL_CERT_FILE`/`GIT_SSL_CAINFO` settings survive unchanged.
- **Password redaction closed before the first durable write (`r4`)**: new rules cover any non-empty (`>= 1` character) `password`/`passphrase`/`ssh_password` assignment, including JSON-escaped double-quoted assignments, CLI password flags, and Chinese password prompt sentences (a password label followed by 是, 为, a colon, or whitespace and a value). Only the secret value is replaced, preserving surrounding structure, with zero false positives on documentation such as 密码输入 / 密码学 / 密码回退.
